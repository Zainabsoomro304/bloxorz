Slide 03 prep

Discrete game state

- The puzzle is stored as data, not guessed from the mesh.
- Main state: x, z, orientation.
- Standing block occupies one cell.
- Lying block occupies two cells.
- Legal moves are checked from occupied cells.
- The same occupied cells also decide falls, switches, and wins.

Key point:
The graphics are smooth, but the puzzle logic stays exact.

Slide 04 prep

Movement and animation

- A key press first asks: is this move legal?
- If legal, the state changes to the next grid position.
- The mesh then animates toward that state.
- Position interpolation makes movement smooth.
- Quaternion rotation gives clean 3D rolling.
- Snapping after the move prevents floating-point drift.

This connects gameplay logic with transformation in graphics.

Slide 05 prep

Level mechanics

- Normal tile: basic support tile.
- Fragile tile: unsafe when the block stands upright.
- Heavy switch: only works with upright block pressure.
- Soft switch: works when any occupied cell touches it.
- Bridge: changes the board during the level.
- Teleport: splits the block into two smaller cubes.
- Merge: split cubes must rejoin from valid adjacent cells.
- Goal: only accepts a standing full block.

Best explanation:
Each mechanic changes the move-validation graph.

Slide 06 prep

Graphics pipeline

- Geometry: block, tiles, bridge meshes, particles.
- Model transform: object position, rotation, scale.
- View transform: camera position and direction.
- Projection: 3D scene mapped to perspective screen space.
- Rasterization: triangles become screen fragments.
- Fragment shading: lights and materials affect final color.
- Frame buffer: final pixels are written to the canvas.

Use this slide to show direct lecture connection.

Slide 07 prep

Scene setup

- PerspectiveCamera gives depth and 3D viewing.
- MeshPhysicalMaterial handles lighting-based surfaces.
- DirectionalLight creates main shadows.
- AmbientLight keeps dark areas readable.
- Fog adds depth.
- SMAA reduces jagged edges.
- Bloom/vignette are postprocessing effects.
- GPU path tracing is optional and has fallback behavior.

Important:
Do not claim custom block shaders. Three.js materials use WebGL shader programs internally.

Slide 09 prep

BFS solver

- BFS means breadth-first search.
- It explores moves level by level.
- First found solution is shortest.
- State includes position, orientation,
  bridge state, and split state.
- Hint uses the next move from BFS.
- check-levels verifies official pars.
Verified shortest paths:
1  First Steps      8
2  Over the Edge    7
3  Fragile Ground   6
4  Open Sesame      6
5  Heavy Duty      12
6  Split Decision   8
7  Twin Bridges    13
8  The Gauntlet    15

Command:
npm run check:levels

Code files

- levels.js: level data, themes, pars.

- editor.js: custom level editing and saving.

- particles.js: dust, shatter, sparkles, win feedback.

If code is requested, start from controls.js and grid.js.
